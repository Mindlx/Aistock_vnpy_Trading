## 背景

2026年6月29日，c1test统一回测系统刚刚上线，跑出了第一份全系统体检报告。

## 当时的系统状态

| 系统 | c1test 准确率 | 一句话 |
|------|:------------:|--------|
| 融合 | 57.7% | 诚实的基线 |
| ML sentiment_score | **67.7%** | 数字直觉已经足够好 |
| ML operation_advice | 27.5% | 文字表达有严重问题（后修复） |
| LY OOS | 49.0% | 接近随机，因子管道待诊断 |
| AT | 54.8% | 新 prompt 第一天 |

**语义差距：40个百分点** — ML 的"内心"（评分）和"口头表达"（文字建议）严重脱节。

## 当时的认知和决策

### 核心信念（来自发起人的判断）

1. **ML 的文字问题不影响融合**。文字是给人看的，融合引擎只吃评分——正是这个判断支撑了 v4.0 精度校准映射的方向。

2. **LY 49.0% 不是真实水平**。数据导入存在管道问题（RF 因子 + 158 因子），并非 LY 架构的问题。LY 的价值在于"永远用客观数据说话，没有任何干扰"——这是三个子系统中最稀缺的品质。

3. **AT 54.8% 是第一天**。AT 过去用了美股提示词跑 A 股，多代理辩论体系与 A 股高度不适应。6月29日是重写后的第一天——这个数字是起点，不是终点。

4. **融合 57.7% 不是"投资建议准确率"**。融合系统是"全面观察员"和"调优工具"。它的真正使命是提供三个子系统协作质量的体检报告。

### 技术架构的定调

- **c1test** 的价值不是"系统能跑多好"，而是"让子系统的每一次进步都能被跨系统看见"
- **精度校准映射（v4.0）** 的方向是正确的——加强 sentiment_score 路径，减少对 operation_advice 文本的依赖
- **零侵入原则**：融合系统不修改子系统代码，通过数据层面的编排和校准来协同

### 愿景

> 如果有一天，三个子系统在融合系统的协同下，能发挥 1+1+1 > 3 的能力。
