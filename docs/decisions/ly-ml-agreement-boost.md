# LY+ML 同向价值最大化 — c1skill 论证

> 分析日期: 2026-06-24
> 状态: Phase 1 完成（分析文档），Phase 2 诊断脚本待执行，Phase 3 逻辑改动待数据支持

---

## Stage 0 — 原架构理解

当前线性融合（`_fuse_linear`）采用固定权重加权平均：

```python
fusion_score = ly_score * 0.37 + ml_score * 0.50
```

分歧检测（`_detect_disagreement`）只做布尔标记：`has_disagreement` 分歧时仓位上限为"1成"。

**关键发现**：分歧有惩罚逻辑（仓位上限），但**同向没有奖励逻辑**。同向（双方方向一致）时融合得分自然更极端，但 L7 映射未利用"双系统印证"这一额外信号。Oracle v3 移除了分歧惩罚（避免退化输出），但也未补充同向奖励。

### 当前融合管线

1. 归一化各系统信号
2. 固定权重加权平均（LY 0.37, ML 0.50, AT 0.00）
3. 分歧检测 → `has_disagreement` 标记 → 分歧时仓位上限"1成"
4. 映射到 L7 信号 + 仓位建议

## Stage 1 — 问题定义

| 维度 | 内容 |
|------|------|
| **问题** | 融合引擎对 LY+ML 同向和反向使用相同映射逻辑，未利用"同向 70.6% 准确率"这一证据 |
| **严重程度** | **MEDIUM**（有改进空间但非致命） |
| **影响范围** | `_get_final_decision()` → 信号等级 → 仓位建议 |
| **覆盖率** | 同向覆盖 18.7% 样本（同向看多 n=9, 同向看空 n=25） |

## Stage 2 — 跨学科著作证据

| 领域 | 著作 | 相关论述 | 方向 |
|------|------|---------|:----:|
| 量化组合管理 | Grinold & Kahn APM | 主动管理基本定律：IR = IC × √BR。两个独立信号同向时有效广度不变但 IC 提高，应提高置信度 | ✅ 支持 |
| 量化系统交易 | Carver Systematic Trading | 头寸规模 = 预期收益 / 风险。多个独立信号收敛时预期收益上升，分歧时下降 | ✅ 支持 |
| 统计学习 | Hastie ESL | 集成学习：基学习器独立且同向时集成置信度显著提高。贝叶斯最优组合应考虑联合分布 | ✅ 支持 |

**独立收敛**：三个领域从不同方法论指向同一结论——多信号同向时置信度应上修。

## Stage 4 — 反方论据

| 反方论点 | 有效性 | 回应 |
|----------|:------:|------|
| **小样本(n=34)**，同向看多仅 n=9 | 🟡 部分有效 | 同向看空 n=25 已足够。且三大理论独立收敛，非数据挖掘 |
| **过拟合风险**：观察数据→调整参数的循环 | 🟡 部分有效 | 解决方案：Phase 2 先出诊断脚本，积累 OOS 数据再改逻辑 |
| **当前 fusion 已 55.5%**，边际改进空间有限 | 🟢 有力 | 同向仅占 18.7% 样本。改进上限 ≈ +4.1pp。非革命性 |
| **违背 Oracle v3 保守原则**（分歧惩罚已移除） | 🔴 强有力 | 新增条件逻辑可能引入新的退化路径。需要 OOS 数据支撑 |

**最大改进空间不在同向奖励，而在单一系统场景的降权**：
- 仅 LY 有信号（占 31.9%）准确率 = 50%（随机）
- 仅 ML 有信号（占 23.6%）准确率 53.5%（弱正向）
- 这两个场景占据了系统的 55.5% 样本

## Stage 5 — 方案设计

### Phase 1（零风险）✅ 已完成
本文档的撰写与保存。

### Phase 2（诊断脚本）
`scripts/diagnose_agreement.py`
- 遍历 `bt_predictions` + 未来 14 天融合数据
- 输出各场景准确率对比
- 模拟不同权重调整方案的增益

### Phase 3（逻辑改动，依赖 Phase 2 数据）
如果 Phase 2 显示 OOS 数据中以下之一成立：
1. **仅 LY 有信号**时融合准确率持续 ≈50% → 仅 LY 有信号时降权 LY 至 0.2
2. **同向看多**时融合准确率持续 >80% → 同向时 fusion_score × 1.1
3. **反向**时融合准确率持续 <50% → 反向时仓位降一档

改动位置：`src/fusion_engine.py` 中 `_get_final_decision()` 或 `_fuse_linear()`

改动量：3-5 行代码
