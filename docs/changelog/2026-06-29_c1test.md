## 变更一：ml 精度校准映射 v4.0

### 背景
回测数据显示 ML 的 sentiment_score 方向准确率存在极端不对称：看空 89-100% vs 看多 38-56%。原映射用对称的 ±1.5 处理所有信号，系统性高估低精度看多信号、低估高精度看空信号。

### 映射变更

| Sentiment | 旧 L7 | 新 L7 | 依据 |
|:---------:|:----:|:----:|------|
| 0-19 | -1.5 | **-3.0** | 100.0% acc |
| 20-30 | -1.5 | **-2.5** | 89.0% acc |
| 31-40 | -1.5 | **-2.0** | 92.8% acc |
| 41-48 | -1.5 | -1.5 | 92.8% acc, 保留最强信号段 |
| 49-51 | 0.0 | 0.0 | 严格中性 |
| 52-59 | +1.5 | **+0.8** | 56.2% acc, 保守 |
| 60-79 | +1.5 | **+1.0** | 38.2% acc, 阻尼 |
| ≥80 | +1.5 | +1.5 | extrapolated |

### 论证强度
c1skill 8 阶段 + 3 学科 5 著作独立收敛。Stage 4 反方论据吸收：52-59 保守 +0.8（非 +1.0）。Stage 7 判定为增强，非违背。

### 验证
- 68/68 测试通过，0 回归
- 风险等级 LOW

## 变更二：c1test 统一回测系统

### 问题
三套独立回测系统（融合/ML/LY）使用不同 DB、指标、入口、报告格式，无法一站对比。AT 无独立回测。ML 独立回测只测 operation_advice（22%），不测 sentiment_score（62%），严重低估 ML。

### 解决方案

```
c1test.py (编排器)
├── Phase 1: 融合回测 (子进程 backtest.py + 直查 bt_results.db)
├── Phase 2: LY 独立回测 (子进程 lynx_signal.py --backtest)
├── Phase 3: ML 独立回测 (直查 stock_analysis.db)
├── Phase 4: AT 独立回测 (TA JSON + stock_daily JOIN)
├── 变化检测: 对比 last_run.json → 红黄绿告警
└── 统一报告: unified_report.json + .md + last_run.json
```

### 盲区修复

| 盲区 | 之前 | 之后 |
|------|------|------|
| AT 独立回测 | ❌ 不存在 | ✅ 54.8% (34/62) |
| ML sentiment 准确率 | ❌ 只从融合间接看 | ✅ 直查 **67.7%** |
| 统一回测入口 | ❌ 3 套系统各自为政 | ✅ `c1test.py` 一个命令 |
| 变化检测 | ❌ 每次人工比数字 | ✅ 自动红黄绿告警 |
| LY 格式健壮性 | ⚠️ 无保护 | ✅ 格式守卫+原始输出回退 |
