# AT 看多失败 & ML 可用率诊断报告

> 生成日期: 2026-06-16 | 源于 `bt_results.db` 100 样本分析

## 一、AT 看多 0% 根因

### 数据

AT 在 100 个样本中仅 6 次看多（at_dir=1），全部错误（0% 正确，p=0.03 显著低于随机）。

| 日期 | 股票 | AT得分 | 实际涨跌 | LY方向 | ML方向 |
|------|------|--------|---------|--------|--------|
| 6/2 | 601801 皖新传媒 | +2.06 | -1.91% | 中性 | 中性 |
| 6/2 | 603189 *ST网达 | +2.06 | -1.15% | 看空 | 看空 |
| 6/4 | 603189 *ST网达 | +2.06 | -1.11% | 中性 | 中性 |
| 6/4 | 603557 *ST起步 | +2.06 | -2.04% | 中性 | 中性 |
| 6/5 | 603189 *ST网达 | +2.06 | -3.77% | 看空 | 中性 |
| 6/5 | 603557 *ST起步 | +2.06 | -3.54% | 中性 | 中性 |

### 特征

1. **全部是弱势/ST 股**: 2/3 的股票是 *ST 股票（退市风险极高）
2. **全部是 LY 不同意的**: 6 次中 LY 从未同步看多，要么看空要么中性
3. **置信度始终为 +2.06**: 从未达到 +3.0（强烈看多），说明 AT 自己也"不太确信"
4. **这些股票在回测期都在跌**: *ST网达 -0.21%、*ST起步 -0.51%、皖新传媒 -0.66%

### 根因诊断

AT 的看多偏见类似于 **value trap 效应**——"跌多了应该会反弹"→"这股票便宜"→"看多"。这在 ST 股上特别明显。AT 的 Bull Researcher prompt 包含了"强调增长潜能和积极指标"的倾向，但没有足够的"不接飞刀"约束。

**建议**: 在 AT 的 Researcher prompt 中增加"持续下跌的 ST 股不因价格低就买入"的规则。

## 二、ML 可用率 51% 根因

### 数据

ML 51/100 样本可用（51%）。宕机模式：

| 日期 | ML | LY | AT | 备注 |
|------|-----|-----|-----|------|
| 5/30 | 0/10 | 10/10 | 4/10 | 系统启动日 |
| 6/1 | 10/10 | 8/10 | 4/10 | ✅ |
| 6/2 | 10/10 | 7/10 | 9/10 | ✅ |
| **6/3** | **0/10** | **5/10** | **0/10** | ❌ **874 errors** |
| **6/4** | **0/10** | **5/10** | **8/10** | ❌ 连续宕机 |
| **6/5** | **0/10** | **4/10** | **8/10** | ❌ 连续宕机 |
| 6/8 | 1/10 | 10/10 | 10/10 | ⚠️ 仅恢复1只 |
| 6/9-6/15 | 10/10 | 10/10 | 10/10 | ✅ 正常运行 |
| **6/16** | **0/10** | **10/10** | **10/10** | ❌ 今日宕机 |

### 特征

1. **间歇性宕机**: 6/3-6/5 连续 3 天挂，6/8 部分恢复，6/9-6/15 正常，6/16 又挂
2. **不是 scheduler 崩溃**: service 状态一直是 `active (running)`
3. **6/3 日志有 874 个 ERROR**（非正常）
4. **LY 和 AT 不受影响**: 同期 LY 和 AT 有数据，说明是 ML 独有的问题

### 根因诊断

ML scheduler 本身没有挂（service running），但内部的分析管线执行失败了。874 个 ERROR 可能是：
- 外部 API（akshare 或其他上游数据源）超时
- ML 的 LLM 调用（DeepSeek API）返回异常
- 数据库写入冲突

**建议**: 检查 ML 日志 `stock_analysis_debug_20260603.log` 中的 ERROR 类型分布。如果是 API 超时，设置更长的超时或重试机制。如果是 DeepSeek API 问题，需要增加 fallback channel。

## 三、综合发现

两个问题都指向同一个根源：**外部依赖的可靠性**。

- AT 的错误看多 → prompt 缺少"不追弱势股"约束 + 数据源不稳定
- ML 的宕机 → 外部 API 调用的稳定性问题
- 二者都是系统性的，可以通过代码修改改善
