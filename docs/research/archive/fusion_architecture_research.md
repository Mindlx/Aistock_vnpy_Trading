## 1. 背景与问题陈述

### 1.1 项目概览

Aistock_vnpy_Trading 是一个三系统信号融合决策平台。它将三个底层逻辑完全不同的独立股票分析系统整合在一起，通过加权投票机制输出最终投资建议。

| 系统 | 简称 | 方法 | 核心输出 | 本质 |
|------|------|------|---------|------|
| lynx_vnpy | **ly** | RandomForest 量化模型 | 上涨概率% + 5级信号 | 纯数学/确定性 |
| MindLynx-Aistock | **ml** | 因子计算 + LLM 推理 | 综合评分 0-100 + 操作建议 | 因子+LLM混合 |
| mind_TradingAgent | **at** | 多智能体辩论 (LangGraph) | 5级评级 + 决策摘要 | 纯LLM/随机性 |

### 1.2 原始设计方案

最初的设计方案基于**线性加权平均**：

```
融合总分 = ly得分 × 0.35 + ml得分 × 0.35 + at得分 × 0.30
```

这一方案将三个系统视为同等质量的信号源，采用固定权重融合。完整的设计方案最初由用户以 ~575 行的技术文档形式提出，包含完整的目录结构、映射表和融合算法，并附有明确声明：**仅供学习和研究目的，不构成任何投资建议**。

### 1.3 核心问题

随着分析的深入，我们发现原始设计存在一个**根本性的假设错误**：

> **线性加权平均假设三个系统是同等质量的信号源，但事实远非如此。**

这一认知是整个架构重设计的起点。

## 2. 第一轮分析：方案可行性评估与 Oracle 初次修正

### 2.1 分析方法

2026-05-29，通过并行探索三个系统的实际代码库，并咨询 Oracle 进行架构评估，对原始设计方案进行了全面的可行性分析。

三个系统的实际输出与设计文档的差异通过直接代码审查发现：

| 项目 | 设计文档写的 | 实际系统输出 |
|------|------------|------------|
| **lynx 信号** | "关注/买入" | `"🟢 买入"`(含 emoji) |
| **lynx 置信度** | `confidence` 字段 | `prob_up` (0-100%)，无独立 confidence |
| **lynx 输出** | 假设有文件输出 | **无文件输出**（仅企业微信推送） |
| **MindLynx 信号** | 持有/观望/卖出(3级) | 买入/加仓/持有/减仓/卖出/观望(6种) |
| **TradingAgent 评级** | Strong BUY/BUY/HOLD/SELL/Strong SELL | **Buy/Overweight/Hold/Underweight/Sell** |
| **TradingAgent 存储** | MongoDB | 文件系统(JSON + Markdown) |

### 2.2 Oracle 识别的 3 项重大设计漏洞

#### 漏洞 1：分歧 ≠ 中性 ⚠️ 严重

**表现**: `ly(+0.90) × 0.35 + at(-0.80) × 0.30 ≈ 0.06 → 中性`

**Oracle 判定**: 强分歧是最重要的风险信号，应该惩罚而非中和。

**代码修正**: 添加 `_detect_disagreement()` + `_compute_uncertainty_penalty()` → 分歧时扣减融合分 + 仓位上限 1成。

#### 漏洞 2：置信度信息被丢弃 ⚠️ 中等

**表现**: ly 的 `prob_up=90%` 和 `prob_up=51%` 如果都是"买入"，被映射到相同的 +0.8。

**Oracle 判定**: # 丢弃了最重要的信号质量信息。

**代码修正**: lynx 信号乘以 `prob_up/100` 做自然调制；MindLynx 按评分区间细化持有/观望子档位。

#### 漏洞 3：系统缺失时错误降分 ⚠️ 中等

**表现**: 原设计在系统缺失时直接降分。

**Oracle 判定**: 缺系统时应**重分配权重**而非简单降分。

**代码修正**: `_compute_adjusted_weights()` 将缺失系统权重按比例分配给剩余系统，标记 `is_degraded`。

### 2.3 初步结论

Oracle 评估结论：**方案总体可行，但三处设计漏洞必须修复**。线性积分方案在初期是可用的选择，因为三个系统的信号源在算法层面正交（ML量化 / LLM推理 / Multi-Agent辩论），低相关度下线性加权效果已足够好。

所有修正已在 `src/fusion_engine.py` 和 `src/normalizer.py` 中实施。

> **讨论节点**: 用户在此阶段明确要求"零侵入"原则——所有融合系统文件包括数据读取都必须存放在 `Aistock_vnpy_Trading/` 文件夹内，不修改三个原有系统的任何文件。这直接影响了 `src/data_loader.py` 的设计：采用 `sys.path` 导入 lynx_vnpy 核心函数、解析 MindLynx 已生成的 Markdown 报告、读取 TradingAgent 的 JSON 状态日志。

## 5. 第四阶段：深度融合分析 — Oracle 架构重设计

### 5.1 触发背景

经过三个阶段的实践，一个更本质的问题浮现出来：**线性加权平均从根本上存在缺陷**，因为它假设三个系统是"同等级"的信号源。但根据前面的工作，我们已经清楚地认识到：

| 系统 | 本质 | 预测可靠度 | 幻觉风险 |
|------|------|-----------|---------|
| ly | **纯数学** (RandomForest predict_proba) | 高 | 无 |
| ml | **因子+LLM混合** (~40%数学+~60%LLM) | 中 | 中 |
| at | **纯LLM角色扮演** (8-12次LLM调用) | 低 | 高 |

### 5.2 用户的关键洞察：确定性—随机性光谱

> **三个系统位于"完全确定性 → 完全随机性"的光谱上，需要不同的融合策略。**

```
ly (纯数学) ───────── ml (混合) ───────── at (纯LLM)
    确定性                       随机性
[数学否决权]              [半分析]             [幻觉高发]
```

这一洞察是 Oracle 架构重设计的核心理念：不是通过调整权重，而是通过理解每个系统的本质来决定它在融合中的角色。

### 5.3 Oracle 深度分析发现

#### 5.3.1 权重失真量化

当前的线性加权方案存在严重的权重失真：

| 系统 | 标称权重 | 映射范围 | 原始输出格式 | 实际影响力 |
|------|---------|---------|------------|-----------|
| ly | 30% | -0.8 ~ +0.8 | prob_up 0-100（数学概率） | 受 prob_up 连续调制 |
| ml | 35% | -0.6 ~ +0.6 | sentiment_score 0-100（LLM生成） | **27.6%** ⚠️（范围窄） |
| at | 30% | ±0.9（离散5级） | **仅分类标签**（Buy/Sell等，无数值） | **35.5%** ⚠️（映射值宽） |

**at 凭借 normalizer 赋予的 ±0.9 映射值，实际占据了 35.5% 的融合影响力，超过 ml 的 27.6%**，尽管前者是纯粹 LLM 角色扮演（原始输出无数值）、后者有 40% 数学基础。

> ⚠️ 注：上表中的"映射范围"是指 `src/normalizer.py` 中映射表赋予的范围，并非三个系统的原始输出范围。详见 `docs/c1skill-review.md` Stage 2 代码级验证。

#### 5.3.2 Oracle 建议的四项修正

| # | 问题 | 建议 |
|---|------|------|
| 1 | 得分范围不一致导致隐性权重偏移 | **范围归一化**：所有系统映射到 ±0.6 以内 |
| 2 | 50% 附近信号被当作"轻微看多"而非"不确定" | **对称中性带**：±0.15 以内视为中性 |
| 3 | 分歧检测阈值对称但不合理 | **调整分歧阈值**：根据系统类型设置非对称阈值 |
| 4 | 不确定性惩罚削弱了高置信度信号的权重 | **降低默认不确定性惩罚基数** |

### 5.4 Oracle 架构设计：可靠性调制贝叶斯融合

#### 5.4.1 核心架构

```
三阶段融合:
  Tier 1: ly (确定性核心)  →  数学否决权
  Tier 2: ml (混合分析)    →  半分析验证
  Tier 3: at (随机信号)    →  LLM sanity check
```

#### 5.4.2 核心公式

```
有效权重 = 系统基础可靠度(α) × 信号置信度(c) × (1 - 幻觉度(h))

融合概率 = Σ(有效权重 × 各系统看涨概率) / Σ(有效权重)
```

#### 5.4.3 关键参数

**基础可靠度 (α)** — 由系统本质决定的固定值：

| 系统 | α | 理由 |
|------|---|------|
| ly | **0.75** | sklearn 概率输出，可回测，100% 可重复 |
| ml | **0.55** | ~40% 数学基础 + ~60% LLM，混合误差 |
| at | **0.40** | 纯 LLM 角色扮演，角色不一致 + prompt 敏感，最高随机性 |

当置信度和幻觉度相等时，ly→at 产生约 2 倍权重乘数，这是有意的：校准过的确定性模型应始终主导未校准的随机模型。

**幻觉检测 (h)**:

| 系统 | h 公式 | 默认值 |
|------|--------|--------|
| ly | h=0 (无需幻觉检测) | **0** |
| ml | `factor_deviation_penalty + direction_contradiction_penalty` | **0.15** |
| at | `1 - debate_consistency_score + role_check_penalty` | **0.30** |

**置信度校准 (c)**:

| 系统 | c 公式 | 范围 |
|------|--------|------|
| ly | `\|prob_up - 50\| / 50` | [0, 1] |
| ml | `\|score - 50\| / 50 × 0.85` | [0, 0.85] |
| at | `debate_consistency_score × 0.50` | [0, 0.50] |

#### 5.4.4 数学否决权

当 ly 具有强方向性判断且与融合结果冲突时：

```python
if |P_ly − 0.50| > 0.30 and sign(P_ly) ≠ sign(P_fused):
    if ml == at == -ly:  # 2v1, 随机系统一致反对确定性系统
        P_final = 0.40 × P_ly + 0.60 × P_fused  # 不完全采用 ly
    elif ml == ly:       # ly+ml (数学+混合) vs at (纯LLM)
        P_final = 0.80 × P_ly + 0.20 × P_fused  # 信任数学
    elif at == ly:       # ly+at vs ml
        P_final = 0.70 × P_ly + 0.30 × P_fused
```

#### 5.4.5 投票质量分级

| 系统 | 投票类型 | 等效票数 | 理由 |
|------|---------|---------|------|
| ly | "数学投票" | **1.0** | 确定性的数学输出 |
| ml | "半分析投票" | **0.7** | 因子部分的确定性 |
| at | "咨询投票" | **0.4** | 纯随机，仅供咨询 |

#### 5.4.6 方案验证示例

**场景**: ly 强烈看空, at 幻觉看多

```
当前方案:
ly(-0.60) × 0.35 + at(+0.90) × 0.30 = -0.21 + 0.27 = +0.06 → 中性 ❌

新方案:
ly: P=0.15, c=0.70 → w_ly = 0.75 × 0.70 = 0.525
at: P=0.85, c=0.30, h=0.70 → w_at = 0.40 × 0.30 × 0.30 = 0.036
→ ly 有效权重是 at 的 14.6 倍 → 看空 ✅
```

> **讨论节点**: 此方案是纯分析方案，尚未实施。用户需确认后再进入编码阶段。

## 6. 第五阶段：Bug 发现与修复

### 6.1 normalizer.py 的 prob_up 语义 Bug

在准备实施过程中，发现 `src/normalizer.py` 中存在两个关键 bug：

#### Bug 1：阈值方向错误

```python
# 错误的代码
if confidence < 0.35:  # prob_up < 35 → 视为无效
    return 0.0, False
```

当 `prob_up=20`（强烈看空，80% 概率下跌）时，`20 < 35` 触发"信号无效"，最强看空信号被丢弃。

**本质**: `prob_up` 是看涨概率，不是信号强度。`prob_up < 35` 意味着看涨概率极低→实际上是强看空信号。应该用 `|prob_up - 50| < 15` 来判断"不确定"，而非用单侧阈值。

**修复**: 改用信号强度 `|prob_up - 50|` 作为置信度判断，而不是看涨概率的绝对值。

#### Bug 2：看空调制使用了错误变量

```python
# 错误的代码
if signal in ("谨慎", "回避"):
    return base_score * prob_up, True  # prob_up=20 时看空信号被削弱 80%
```

看空信号使用了 `prob_up`（看涨概率）而非 `100 - prob_up`（看跌概率）。当 `prob_up=20` 时，"回避"信号本应乘以 0.80 的看跌概率，却实际乘以了 0.20。

**修复**: `src/normalizer.py` 第 92 行：在 `normalize_lynx()` 中，看空信号（base_score < 0）使用 `(100.0 - prob_up) / 100.0`（即 prob_down）替代错误的 `prob_up` 作为信念强度乘数。

### 6.2 "关注"基础值修正

"关注"信号的映射值从 `0.8` 修正为 `0.55`，因为原始值过高，导致 ly 的"关注"信号（基础看多）与 at 的"Buy"（强烈看多）产生不恰当的权重关系。

### 6.3 修复结果

测试覆盖从 23 个扩展至 44 个，42/44 通过（2 个为预期行为边界情况）。

## 7. 最终方案：可靠性调制贝叶斯融合架构

### 7.1 架构总览

```
┌─────────────────────────────────────────────────────────────────────┐
│                        可靠性调制贝叶斯融合                            │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Tier 1: ly (确定性核心)          Tier 2: ml (混合分析)              │
│  ┌─────────────────────┐         ┌──────────────────────┐           │
│  │ α = 0.75            │         │ α = 0.55             │           │
│  │ c = |P50-50|/50     │         │ c = |s-50|/50×0.85   │           │
│  │ h = 0 (无需检测)    │         │ h = 因子偏差+方向矛盾  │           │
│  │ 数学投票: 1.0 票     │         │ 半分析投票: 0.7 票    │           │
```

### 7.2 与当前方案的全面对比

> **重要说明 — 分歧检测已实施**：当前代码中已实现 `_detect_disagreement()` + `_compute_uncertainty_penalty()`，极端分歧场景已正确处置。
> 以 ly=+0.90, at=-0.80 为例：
> - 原始设计（无检测）: +0.06 → 中性 ❌
> - **当前代码（已实施）**: -0.525 → 强烈看空 ✅
> - 新方案: ly 有效权重 14.6 倍 → 看空 ✅
> 
> 分歧检测已彻底修复了原始设计最严重的问题。新方案在此基础上做精细化改进，而非革命性替代。

| 维度 | 当前方案 (线性加权) | 当前代码（分歧检测实施后） | 新方案 (可靠性调制) |
|------|-------------------|------------------------|-------------------|
| **权重** | 固定 0.35/0.35/0.30 | 固定权重 + 权重重分配 | **动态**: ly α=0.75, ml α=0.55, at α=0.40 |
| **融合空间** | 得分空间 [-1, +1] | 得分空间 [-1, +1] | **概率空间** [0, 1] |
| **置信度** | 部分使用 | **prob_up/100 调制** | **全部校准**: ly/ml/at 各有公式 |
| **幻觉检测** | 无 | 无 | **三级**: ly 无需, ml 因子偏差, at 辩论一致性 |
| **分歧处理** | 对称 (±0.1) | **分歧惩罚 0~0.6 + 仓位≤1成** | **非对称层级覆盖**: ly>ml>at |
| **系统缺失** | 固定降分 | **权重重分配** + 降级标记 | **权重重分配** + 降级标记 |
| **输出映射** | -1~+1 → 5档 | -1~+1 → 5档 | **P 0~1 → 5档** (更自然) |
| **验证参数** | 固定阈值 | 固定阈值 | **全参数化**: settings.yaml 可调 α/c/h 公式 |

### 7.3 关键设计原则

1. **本质区分**: 每个系统基于其数学本质（确定性 vs 随机性）被区别对待，而非等同看待。
2. **概率空间**: 在概率空间 [0,1] 进行融合，比在得分空间 [-1,+1] 具有更坚实的数学基础。
3. **乘法权重**: `α × c × (1-h)` 的乘法公式让低置信/高幻觉信号自然衰减，无需硬阈值。
4. **数学否决权**: 确定性系统在强信号时拥有"一票否决"能力，但通过层级覆盖机制保留少数派可能性。
5. **自我认证幻觉检测**: at 系统的辩论记录本身提供了幻觉检测信号——无需外部验证器。

### B. 重大设计决策

1. **零侵入原则**: 不修改三个原有系统的任何文件，所有适配代码在融合系统内部实现。
2. **数据读取方式**:
   - ly: `sys.path` 导入核心函数直接调用
   - ml: 解析已生成的 Markdown 报告文件
   - at: 读取 JSON 状态日志
3. **通信简称**: 沟通中使用 ly/ml/at，代码中保持完整命名不混淆。
4. **概率空间**: 新架构在 [0,1] 概率空间融合，而非 [-1,+1] 得分空间。
5. **数学否决权触发阈值**: `|P_ly − 0.50| > 0.30`，即 ly 的看涨概率 <20% 或 >80% 时才触发。

### D. v3.0 7 级语义对齐（2026-05-30）

在完成 Oracle 架构设计后，进一步发现三个系统的分级粒度不同，强行 5 级映射存在根本性语义错误。

**核心洞察**: 三个系统参考系完全不同
| 系统 | 参考系 | 本质 |
|------|--------|------|
| ly | 置信度 | "涨的概率是多少？" |
| ml | 操作建议 | "应该怎么做？" |
| at | 研究评级 | "值得投资吗？" |

**关键修正**: ml 的"持有"≠弱看多
- "持有"的语义是"继续持有不动"，不是买入信号
- 旧映射: 持有=0.45 (偏多) ❌
- 新映射: 持有=L7=0 (中性) ✅

**7 级统一空间**:

| L7 | 范围 | ly (prob_up) | ml | at |
|----|------|-------------|----|----|
| +3 | [2.0, 3.0] | ≥85% (logit) | 买入 | Buy |
| +2 | [1.0, 2.0) | ≥70% | 加仓 | Overweight |
| +1 | [0.33, 1.0) | ≥55% | — | — |
| 0 | (-0.33, 0.33) | ~50% | **持有/观望** | Hold |
| -1 | (-1.0, -0.33] | ≤45% | — | — |
| -2 | (-2.0, -1.0] | ≤30% | 减仓 | Underweight |
| -3 | [-3.0, -2.0] | ≤15% | 卖出 | Sell |
