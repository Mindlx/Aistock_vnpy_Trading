## Stage 0 — 原架构理解

### 文档定位

本路线提纲是"三篇探讨性报告 + Oracle 战略分析 + 4 份审查报告"的**执行落地层**产物。它不做新的分析论证，而是将前面所有智力产出转化为可执行的任务序列。

### 设计意图

| 要素 | 内容 |
|------|------|
| **最终目标** | 将 c1skill 7 Stage 方法论蒸馏至本地模型，实现本地+API 双轨互备 |
| **核心约束** | C1 任务 3-5 次/周，非每日；核心假设（Oracle < c1skill）未验证 |
| **风险偏好** | 极低（单次训练 ¥0.81，即使完全失败成本也可忽略） |
| **保底收益** | 轨迹数据集 + 训练管线 + 元实践经验，独立于微调成败 |

## Stage 4 — 反方论据

### 4.1 文档可能高估了什么

#### 声明 A: "本地模型可达到 DeepSeek API 质量的 80%"

**反方论据**: 这是**无数据支持的猜测**。Qwen3.6-27B（4-bit 量化）与 DeepSeek V4（MoE 架构，千亿级有效参数）之间存在巨大的能力鸿沟。27B 4-bit ≈ 有效参数 14B 级别，而 DeepSeek V4 可能有数千亿参数。即使 DPO 成功，期望质量达到 API 的 80% 可能是乐观的。

**认定**: ❌ 高估。建议改为"达到 API 质量的 60-80% 视为成功，> 80% 视为超预期"。

---

#### 声明 B: 轨迹采集的操作负担

**反方论据**: "手动/半自动采集"的额外负担可能被低估。完整流程：
1. 完成任务
2. 回忆要采集轨迹
3. 找到对应的 session_id
4. 运行采集脚本
5. 检查提取结果（LLM 可能提取错误）
6. 人工评分
7. 移动到 approved 目录

每次额外增加 5-10 分钟。每天 1-3 条 ≈ 5-30 分钟/天——在持续数月的周期中，这个摩擦可能导致采集意愿下降。

**认定**: 🟡 操作摩擦可能被低估。建议为采集动作设计最小化操作路径（如一个命令完成全部步骤）。

### 4.3 假设检验

| 假设 | 文档立场 | 反方证据 | 判定 |
|------|---------|---------|------|
| **H1: 能找到 ≥5 条历史会话** | 默认成立 | 未验证 session_search 的覆盖率 | ⚠️ 未验证 |
| **H2: Unsloth 容器可访问双卡** | 默认成立 | 未检查 Docker + NVIDIA 配置 | ⚠️ 未验证 |
| **H3: 27B 4-bit 可达 API 80% 质量** | 默认成立 | 模型容量鸿沟显著 | ❌ 高估 |
| **H4: 商业产品有人买单** | 默认有价值 | 未做任何市场验证 | ❌ 纯假设 |
| **H5: 采集摩擦不影响长期坚持** | 默认成立 | 5-10 min/次 × 持续数月可能消磨意愿 | ⚠️ 可能低估 |

### 4.4 是否存在第三方案？

**当前路线**：采集 → DPO → 评估 → 部署

**方案 C（介于之间）**：**直接跳过模型蒸馏，只做数据集沉淀。**

既然核心假设未验证、数据积累周期长、模型效果的提升可能有限，为什么不先专注于**最有确定性的部分**——轨迹数据集本身？

| 动作 | 确定性 | 价值 |
|------|--------|------|
| 积累推理轨迹数据集 | 100% 可执行 | 独立于微调成败，本身就是资产 |
| 训练专属模型 | 30% 把握达到 API 80% 质量 | 有上行空间但不确定 |

**建议**：在路线中增加一个**中途选择点**——当数据积累到 50 条时，可以选择暂停训练，先用现有数据发布一个公开数据集（JSONL），观察社区反馈，再决定是否继续训练。

## Stage 6 — 风险评估与监控

### 6.1 补充风险

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| **采集摩擦导致数据量不足** | 高 | 中 | 自动化的优先级提升；接受"数据集比模型更重要" |
| **历史会话不足以做 Gate 0** | 中 | 低 | 改为从本周起手工记录 5-10 次新任务 |
| **GPU 容器配置冲突** | 低 | 中 | 立即验证 Docker + NVIDIA Container Toolkit + Unsloth |
| **模型蒸馏后未提升实际工作流** | 高 | 低 | 成本 ¥0.81 + 若干小时，可接受 |

### 6.2 监控指标

| 指标 | 健康值 | 告警 | 频率 |
|------|--------|------|------|
| 每周有效轨迹数 | ≥ 2 条 | < 1 条 | 每周日 |
| 分歧率（滚动 10 条） | ≥ 30% | < 15% | 每 5 条新数据 |
| 采集额外耗时 | < 10 min/次 | > 20 min/次 | 每次采集后 |
| 数据质量分（人工） | ≥ 3.5/5 | < 2.5/5 | 每条入库时 |

---

**总体结论**: 实施路线提纲在**操作层面（步骤、门禁、看板）质量很高**，但在**假设检验层面（27B 质量预期、未验证的前提）存在 2 处需要校准**。建议在本周末 Gate 0 之前，先完成 P0 的两项验证（训练环境 + 会话可查性）。

**最具价值的反方发现**: 27B 4-bit 量化后有效参数仅 14B 级别，期望其达到 DeepSeek V4（千亿级 MoE）质量的 80% 可能过于乐观。这个预期应该向下修正为 60-80%。
