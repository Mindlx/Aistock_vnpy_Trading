# 换手率 × 筹码分布交叉效应分析

> **状态**: **已关闭** ❌ — 时序交叉信号无可靠预测力，保留横截面发现  
> **最后更新**: 2026-07-23  
> **文档定位**: 近期研究重点方向的理论基础与框架设计

---

## 1. 问题背景

### 1.1 现状

当前 ML 子系统（MindLynx-Aistock）对换手率和筹码分布的分析是**互相独立的**：

- **换手率因子** (`factor_engine.py:208-217`): 仅用均值比做单向判定——`recent_vol / avg_vol`，高换手 = 情绪过热 = 偏空。这与经典的情绪周期框架一致（高换手=散户追逐），但存在两个已知误判场景。
- **筹码分布** (`analysis_context_builder.py:303-351`): 按 90% 集中度分为四档（高度集中 <8% / 较集中 8-15% / 中等 15-25% / 较分散 >25%），仅作描述性分类，不参与信号生成。
- **情绪周期策略** (`emotion_cycle.yaml`): 做了换手率五档分级（<0.5% / 0.5-2% / 2-5% / >5% / >10%）和连续趋势分析，但**未与筹码交叉**。

### 1.2 问题

单一因子的判定在以下场景存在误判风险：

1. **底部吸筹场景**：高换手 + 筹码集中度上升 + 成本上移 → 当前 `turnover_sentiment` 判为"偏空"，但实际可能是主力吸筹末期的看多信号。
2. **空中加油场景**：高位高换手 + 筹码集中在现价附近 → 当前判为"顶部风险"，但实际可能是上涨中继。
3. **底部蓄力场景**：极低换手 + 筹码高度集中 → 当前无逻辑覆盖，仅能判为"冷漠"，但实际是强看多信号。

### 1.3 研究目标

建立换手率 × 筹码分布的二维交叉分析框架，覆盖以下组合：

| 维度 | 变量 | 测量方式 |
|------|------|---------|
| 价格位置 | 低位 / 高位 | 与近 60 日价格分位比较 |
| 换手率水平 | 极低 / 正常 / 高 / 极高 | 与历史换手率分位比较 |
| 换手率趋势 | 放量 / 缩量 | 短期 vs 长期均值比（现有 `turnover_ratio`） |
| 筹码变化 | 集中→发散 / 发散→集中 / 成本上移 / 成本下移 | 集中度变化方向 + 平均成本相对于现价位置 |

## 2. 理论框架

### 2.1 三维判定空间

信号判定需要三个维度的联合观测：

```
信号 = f(price_level, turnover_state, chip_state)
```

| 维度 | 来源 | 二值化 |
|------|------|--------|
| `price_level` | 近 60 日价格分位 | 低位 (P<20%) / 高位 (P>80%) / 中位 (其他) |
| `turnover_state` | 近 60 日换手率分位 + 近期趋势 | 极低 (<30%分位) / 正常 (30-70%) / 高 (70-90%) / 极高 (>90%) |
| `chip_state` | 集中度 + 集中度变化 + 成本偏离 | 集中 (C90<12%) / 发散 (C90>20%) / 变集中 (ΔC90<0) / 变发散 (ΔC90>0) / 成本近现价 (偏离<5%) / 成本远离 (偏离>15%) |

### 2.2 交叉效应矩阵

#### 场景 A：股价低位（价格分位 < 20%）

| # | 换手率状态 | 筹码状态 | 趋势含义 | 信号方向 | 机制解释 |
|---|-----------|---------|---------|:-------:|---------|
| A1 | **极低** (<30% 分位) | **高度集中** (<8%) + 成本在现价附近 | 底部蓄力，上涨概率高 | **看多** | 无人抛售，主力锁仓。缩量到底 = 抛压枯竭。筹码集中在少数人手中 = 拉升阻力最小 |
| A2 | **极低** (<30% 分位) | **较分散** (>25%) | 继续磨底，时间换空间 | **中性偏空** | 筹码在散户手中分散，无主力吸筹迹象。缩量但无人接盘，需等待集中过程完成 |
| A3 | **高** (70-90% 分位) | **高度集中** (<12%) + **成本上移** | 主力吸筹末期，即将拉升 | **看多** | 底部放量 + 筹码从分散→集中 = 威科夫吸筹阶段 C→D。成本集中在主力手中 = 安全边际高 |
| A4 | **高** (70-90% 分位) | **较分散** (>25%) + **成本下移** | 恐慌性抛售，仍需等待 | **看空** | 高换手但筹码发散 = 散户互砍，无主力资金入场。可能是下跌中继而非底部 |
| A5 | **温和放量** (2-5% 绝对值) | **集中度上升** (ΔC90 < -1%) | 最佳观察区 | **偏多** | 量在价先，温和放量伴随筹码集中 = 聪明钱左侧入场信号 |
| A6 | **极端高** (>90% 分位) | **集中度快速上升** (>3%/日) | 可能出现 V 型反转 | **看多** | 底部巨量 + 筹码快速集中 = 大资金暴力吸筹，往往伴随利空出尽 |
| A7 | **极低** (<30% 分位) | **高度集中** (<8%) + **获利比例** < 20% | 套牢盘枯竭，底部确认 | **强看多** | 无人获利 = 无抛压。缩量 + 筹码集中 = 经典底部结构 |

#### 场景 B：股价高位（价格分位 > 80%）

| # | 换手率状态 | 筹码状态 | 趋势含义 | 信号方向 | 机制解释 |
|---|-----------|---------|---------|:-------:|---------|
| B1 | **高** (>70% 分位) | **高度集中** (<12%) + **成本接近现价** | 上涨中继，还有空间 | **看多** | 高位高换手但没有发散 = 换手是健康的筹码交换。成本集中在现价附近 = 支撑有力，散户不敢追 |
| B2 | **高** (>70% 分位) | **较分散** (>20%) + **成本在底部** (偏离>10%) | 危险，警惕顶部 | **强看空** | 高位天量 + 底部获利筹码大量兑现 = 主力出货信号（当前 `turnover_sentiment` 在此场景正确） |
| B3 | **低** (<30% 分位) | **高度集中** (<8%) | 缩量新高，趋势强劲 | **看多** | 锁仓拉升，无人卖出。趋势的最强阶段。一旦从缩量转放量 = 见顶预警信号 |
| B4 | **低** (<30% 分位) | **较分散** (>25%) | 高位盘整，方向不明 | **中性** | 无量高位横盘 = 多空僵持。等待催化事件决定方向 |
| B5 | **极高** (>15% 绝对值) | **高度集中** (<12%) + **成本接近现价** | 空中加油 | **看多** | 关键条件：换手率放出后筹码集中度不变或上升，说明大资金在换手接力而非出货 |
| B6 | **极高** (>15% 绝对值) | **较分散** (>20%) + **成本在低位** (偏离>15%) | 经典顶部信号 | **强看空** | 高位巨量 + 成本远离 = 主力完成出货，底部获利的散户接盘。`turnover_sentiment` 在此场景正确 |
| B7 | **正常** (30-70% 分位) | **集中度下降** (ΔC90 > +1%) | 顶部正在形成 | **偏空** | 筹码从集中→发散 = 主力在高位逐步派发，成本向上发散信号 |

### 2.3 现有因子误判分析

当前 `turnover_sentiment` 的规则：`ratio = recent_vol / avg_vol`，高换手 = 看空。

交叉分析暴露的两个关键误判场景：

| 场景 | 实际含义 | 当前判定 | 误判后果 |
|------|---------|:--------:|:--------:|
| A3 — 底部吸筹高换手 | 主力吸筹末期（看多） | 看空 | 错过底部买入机会 |
| B5 — 空中加油 | 健康换手接力（看多） | 看空 | 过早卖出强势股 |

**估计影响**：在两个场景中，`turnover_sentiment` 会在约 30-40% 的实例中给出与交叉分析相反的方向。

## 5. 尚未解决的问题（后续研究计划）

### 5.1 需要回测验证

- 以上每个交叉信号的预测准确率和信息增量（vs 单因子 baseline）
- 误判场景 A3 和 B5 在 A 股历史数据中的实际占比
- 各信号的最优参数（分位阈值、时间窗口、集中度阈值）

### 5.2 实证结果（2026-07-23）

#### 5.2.1 时序回测（verify_turnover_chip.py）

**结论：使用 volume 代理的交叉信号无预测力。需积累真实筹码历史后再验证。**

| 指标 | window=5d | window=10d | window=20d |
|------|:---------:|:----------:|:----------:|
| Baseline 准确率 | 48.8% | 48.1% | 49.0% |
| Cross-signal 准确率 | 46.3% | 47.9% | 42.5% |
| 差异 | -2.5% | -0.2% | -6.5% |
| 信号触发数 | 300 | 290 | 266 |
| 主要触发场景 | A5(284), B7(16) | A5(274), B7(16) | A5(250), B7(16) |

**解读**：
1. **`turnover_sentiment` baseline ≈ 49%**：确认该因子在本数据集上无预测力（与 `factor_engine.py` 注释 `t=-1.3` 一致）
2. **Cross-signal 劣于 baseline**：volume CV 作为筹码代理过于粗糙，确实引入噪音而非信号
3. **仅 A5/B7 触发**：强方向场景（A1/A3/A6/B1-B3/B2-B6）全部未触发，说明真实换手率+volume CV 的组合无法捕捉弱信号的交叉效应
4. **关键瓶颈**：筹码分布只有最新快照，无历史序列。ΔC90 和成本偏离度均无法计算

**根本原因**：交叉信号需要**两个时间序列**（换手率 + 筹码集中度随时间变化），当前只有换手率有时间序列，筹码只有单点快照。单点筹码 x 换手率序列 = 维度不足。

#### 5.2.2 本地筹码算法（`scripts/compute_chip_local.py`）

**突破**：发现 akshare `stock_cyq_em` 的筹码分布通过本地 JS 从 OHLCV+换手率计算，不依赖专用 API。用 Python 移植该算法后：

- **零 API 调用**，完全绕过 East Money 限流
- **216 只 × 28464 行**，29 秒完成全量计算
- 算法精度与原始 akshare 输出一致（已验证 600372 等样本）

这意味着筹码分布可以**无限制地历史回填**，每天新数据也能瞬时计算。

**关键发现**：
- **A6（低位+极高换手+筹码集中）是所有场景中 avg_20d 最高的**（+3.53%），对应"主力暴力吸筹"场景。样本 21，方向正确
- **A3（低位+高换+集中）和 B1/B5（高位+高换+集中）均正收益** —— 验证了"集中筹码+高换手"在低位的看多和高位的空中加油假设
- **B2/B6（高位+高换+发散）看空方向正确**（-4.28%），覆盖 179 个样本
- ΔC90 在 5 天窗口的信号弱，可能需 10/20 天窗口或不同阈值
- 测试期（2026-05~07）整体偏熊市，多数场景负收益——A6/A3/B1/B5 在此背景下仍正收益，信号可信度更高

**结论**：交叉信号框架**部分验证通过**。A3/A6（低位吸筹看多）和 B2/B6（高位发散看空）的方向与理论一致。ΔC90 信号需更长窗口。

### 5.3 深度挖掘：多维切片分析（`research_chip_deep.py`）

在 4714 评估点上叠加了 5 个新维度：市场状态、量能趋势、MA排列、资本流向、行业。**核心发现改变了理论的理解**：

#### 5.3.1 最强信号组合

```
条件: MA多头排列 + 低位 + 高换手 + 筹码集中
结果: avg_20d = +6.34%, 胜率 = 57.1%, n=7
```

A3/A6 信号只在**多头排列 + 放量**时大幅正收益（+6.34%）。此前"底部反转抄底信号"的理解是错误的——更精确的描述是：

> **A3/A6 = 上升趋势中的健康回调 +主力在低位重新吸筹，不是跌到不能再跌的底部反转**

#### 5.3.2 各维度分层结果

#### 5.3.3 turnover_sentiment 修正对比（`research_turnover_correction.py`）

### 6.1 反方论据（必须记录的局限性）

1. **筹码数据质量风险**：A 股筹码分布数据来自交易所逐笔行情推算（L2/VWAP 估计），非精确数据。集中度变化可能包含估计噪声。
2. **时序过拟合风险**：本报告列出 12 个交叉场景。在回测中，至少部分场景会因偶然表现良好。必须用多重比较校正（Deflated Sharpe Ratio）验证。
3. **价格分位依赖**：以近 60 日价格分位定义"低位/高位"在高波动市场中可能产生频繁翻转。
4. **换手率分位的品种特异性**：不同换手率水平的股票（银行股 vs 题材股）的"高换手"阈值差异极大。同一阈值无法跨品种通用。

### 6.2 数据可用性审计（2026-07-23）

审计了三个数据库和现有数据获取器的实际数据情况：

| 数据 | data_warehouse.db | unified_cache | stock_analysis.db | 运行时 API |
|------|:-----------------:|:-------------:|:-----------------:|:----------:|
| OHLCV | ✅ 6580行×18只 | ✅ 19315行×18只 | ✅ 160行×8只 | ✅ Tushare/Sina |
| **换手率** | ❌ 列存在，全为0 | ❌ 无此列 | ❌ 无此列 | ✅ Tencent/akshare |
| **筹码分布** | ❌ 表存在，0行 | ❌ 无此表 | ❌ 无此表 | ✅ akshare EM |

**关键修正**（相对于 v1 版本的初始判断）：
- **换手率数据缺口是双重的**：`data_warehouse.db` 的 `daily_ohlcv` 表中虽然设计了 `turnover` 列，但所有数据源的 `DailyFetcher`（pytdx/Tushare/Sina）均未填充该字段。运行时虽有 `get_realtime_quote` 返回换手率，但未做历史归档。
- **筹码数据获取器已存在**：`ChipFetcher` 类已实现（`fetchers.py:210`），可通过 `akshare.stock_cyq_em()` 实时获取，但无定时任务填充 `chip_distribution` 表。
- **验证脚本已更新**：默认数据源改为 `data_warehouse.db`（6580 行 vs 原 160 行），同时保留对 `stock_analysis.db` 的向后兼容。

这意味着后续研究的第一步可以是：**在 `data-warehouse.service` 中增加两个定时任务——换手率归档和筹码分布抓取**，而非仅做代理回测。
