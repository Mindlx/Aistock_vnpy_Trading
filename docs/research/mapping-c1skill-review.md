## Stage 0 — 原架构理解

### 当前映射体系设计意图

`normalizer.py` 中的三个映射表是**将各系统原始输出统一到 [-1,+1] 得分空间**的桥梁：

```
原始输出                    →  映射表         →  归一化得分
ly: prob_up + 信号文本       →  LYNX_SIGNAL_MAP     -0.80 ~ +0.80
ml: sentiment_score + 建议   →  MINDLYNX_SIGNAL_MAP  -0.60 ~ +0.60
at: 5级离散标签              →  TRADINGAGENT_SIGNAL_MAP -0.90 ~ +0.90
```

三个映射表最初由**人工估算**设定，未经系统校准。

## Stage 1 — 声明与事实对照

| 方案声明 | 实际数据支撑 | 判定 |
|---------|------------|------|
| ly 买入=0.70 应高于关注=0.50 | 买入 threshold≥65%，关注≥55%，语义上买入>关注 | ✅ |

## Stage 2 — 代码级证据验证

### 2.1 当前映射值的实际效果验证

```python
# 场景: ly prob_up=70 买入 vs at Buy
# 当前映射:
ly_score = 0.80 * (70/100) = 0.560
at_score = 0.90                 # 固定值
# → at(0.90) > ly(0.56)，LLM标签>数学概率，不合理

# 建议映射:
ly_score = 0.70 * (70/100) = 0.490  
at_score = 0.60
# → ly(0.49) ≈ at(0.60)，差距收窄
```

### 2.2 ml 持有 vs 买入的区分

```python
# 当前: 持有score=65→0.6, 买入score=75→0.6 → 完全一样 ❌
# 建议: 持有score=65→0.5, 买入score=75→0.7 → 差距0.2 ✅
```

**验证**: 从79条ml记录看，持有均分60.3，卖出均分26.2，买入未见数据。没有数据直接反驳"买入>持有"的假设。

## Stage 4 — 反方论据

### 4.1 方案可能低估的

| 声明 | 反方论据 |
|------|---------|
| **at Buy=0.6 可能过低** | at 的 Buy 是8-12轮LLM辩论后组合经理的最终决策，应比单个分析师(ml)的"买入"更有分量。但方案中 at Buy=0.6 与 ml 买入=0.7 相同甚至略低。**建议**: at Buy 至少应 >= ml 买入。 |
| **at 数据不足** | 仅10条记录，全部是 Hold/Underweight，无 Buy/Sell/Overweight 数据。方案对 at 的调整完全基于逻辑推断，无实际数据支撑。 |

### 4.2 方案可能高估的

| 声明 | 反方论据 |
|------|---------|
| **ml 卖出 -0.7 的合理性** | 当前 ml 卖出仅占 10.1%，评分均值 26.2。在 -0.6 基础上再降到 -0.7，与 ly 回避(-0.7)持平——但 ml 的"卖出"是LLM生成的标签，可靠度低于 ly 的 RandomForest 概率。**建议**: ml 卖出保持在 -0.6，不与 ly 回避持平。 |
| **ml 买入 0.7 是否过高** | 建议中 ml 买入 0.7 超过了 ly 买入(0.70×conviction≈0.49)。即一个 LLM 标签比数学模型的输出还高。**建议**: ml 买入应≤ ly 买入的 base_score。 |

### 4.3 方案遗漏的

**贝叶斯模式不受影响** — 优化仅改变 linear 模式的映射值。贝叶斯模式使用 `to_probability()` (sigmoid) + `α×c×(1-h)` 权重，不受映射表影响。需在方案中明确标注。

## Stage 5 — 修复方案评估

### 5.1 修正后的建议值

基于反方论据调整：

| 系统 | 信号 | 原方案 | 修正值 | 理由 |
|------|------|--------|--------|------|
| ly | 买入 | 0.70 | **0.70** | ✅ 不变 |
| ly | 关注 | 0.50 | **0.50** | ✅ 不变 |
| ly | 谨慎 | -0.30 | **-0.30** | ✅ 不变 |
| ly | 回避 | -0.70 | **-0.70** | ✅ 不变 |
| ml | 买入 | 0.70 | **0.65** | ⚠️ 不应超过 ly (0.70×conviction) |
| ml | 加仓 | 0.60 | **0.55** | ⚠️ 对应下调 |
| ml | 持有 | 0.50 | **0.45** | ⚠️ 对应下调 |
| ml | 减仓 | -0.50 | **-0.45** | ⚠️ 对称 |
| ml | 卖出 | -0.70 | **-0.60** | ❌ 保持原值(LLM可靠度低于ly) |
| at | Buy | 0.60 | **0.65** | ⚠️ 应 ≥ ml 买入，体现辩论价值 |
| at | Overweight | 0.40 | **0.45** | ⚠️ 对应上调 |
| at | Underweight | -0.40 | **-0.45** | ⚠️ 对称 |
| at | Sell | -0.60 | **-0.65** | ⚠️ 对应下调 |

### 5.2 最终映射表

```python
# ly（微调）
买入=0.70, 关注=0.50, 观望=0.0, 谨慎=-0.30, 回避=-0.70

# ml（买入>持有，体现区分度）
买入=0.65, 加仓=0.55, 持有=0.45, 观望=0.0, 减仓=-0.45, 卖出=-0.60

# at（压缩范围，Buy≥ml买入）
Buy=0.65, Overweight=0.45, Hold=0.0, Underweight=-0.45, Sell=-0.65
```

### 5.3 影响范围

| 系统 | 变化 | 影响评估 |
|------|------|---------|
| ly | 0.8→0.7, -0.8→-0.7 | 低——prob_up 连续调制占主导，base 变化 0.1 |
| ml | 买入0.6→0.65↑, 持有0.6→0.45↓ | 中——买入>持有差距从0拉到0.2 |
| at | 0.9→0.65, -0.9→-0.65 | **高**——大幅压缩，直接影响 at 在融合中的权重 |
